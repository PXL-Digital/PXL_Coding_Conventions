# C#

## Introduction

Programming according to strict guidelines has a number of advantages:
- the code is readable for every team member;
- as a result, the code is also more maintainable;
- and it gives the entire codebase a professional impression;

## Language

Programming is often done in an international team. That is why we choose 
English as the working language in your source code. This means that you 
write all names (of classes, variables, methods, properties, etc.) and also 
your comments in your code in English.

## Definitions

| Definition      | Description | Example |
| ---        |    ----  |    ----  |
| Pascal Casing | The first letter of each word is written with a capital letter and the other letters are lowercase. | `NewBachelorStudent` |
| Camel Casing   | The first letter of each word, except the first word, is written with a capital letter and the other letters are lowercase. | `newBachelorStudent` |

## Conventions

### CC-01 Use Pascal Casing for class names

```csharp
public class BachelorStudent
{
    // CODE COMES HERE
}
```

### CC-02 Use Pascal Casing for method names

```csharp
public void EnrollInCourse(string courseName, int credits)
{
	// CODE COMES HERE
} 
```

### CC-03 Use Camel Casing for variables and method parameters

```csharp
public void EnrollInCourse(string courseName, int credits)
{
	int totalCredits = credits + GetCurrentCredits();
	// ...
}
``` 

### CC-04 Use the letter `I` as a prefix for interfaces, together with Pascal Casing

```csharp
public interface IEnrollable
{
    void EnrollInCourse(string courseName, int credits);
}
```

### CC-05 Do not use Hungarian notation to name variables

 In the past it was customary to name a variable with a prefix that made the 
 type clear. Sometimes a prefix m_ is also used to indicate that it is an 
 instance variable (member). This is also not allowed.

```csharp
 int nAge;     //FORBIDDEN 
 string sName; //FORBIDDEN
 int m_age;    //FORBIDDEN
 ```

### CC-06 Prefix instance variables with an underscore `_`

By prefixing instance variables with an underscore `_`, you can make a clear
distinction from method parameters and local variables that have the same name.

```csharp
public class Person
{
    private int _age; // not allowed: age or m_age
    ...

    public Person(int age)
    {
        _age = age;
    }
}
```

### CC-07 Use meaningful names for classes, methods and variables.

The name of a variable, method or class should tell something about its 
reason for existing. If a name requires a comment, the name does not reveal 
its intent.

Not:

```csharp
int d; // elapsed time in days
```

But:

```csharp
int elapsedTimeInDays;
```

Also do not use abbreviations, even if they would be clear to the reader:

Not:

```csharp
string addr; 
int sal; 
```

But:

```csharp
string address; 
int salary;
```

### CC-08 Do not use variable names consisting of a single character

No `i`, `n`, `c`, etc. But do use `index`, `numbers`, `count`, etc.

An exception can be made for loop variables:

```csharp
for (int i = 0; i < count; i++)
{
    // CODE COMES HERE
} 
```

An exception can be made for parameters in lambda expressions:

```csharp
var evenNumbers = numbers.Where(n => n % 2 == 0);
```

### CC-09 Name instances of User Interface (UI) components with a meaningful name, followed by the class name of the component in question.

In C#:
```csharp
Button cancelButton = new Button();
```

In XAML:
```xml
<Button x:Name="cancelButton" ...></Button>
```

When code generated by Visual Studio conflicts with the rules for method 
names, you do not need to change it. For example:

In XAML:
```xml
<Button x:Name="cancelButton" Click="cancelButton_Click"></Button>
```

In C#:
```csharp
private void cancelButton_Click(object sender, RoutedEventArgs args)
{
    // This method can be generated by Visual Studio
}
```

### CC-10 Use at most one public class per file
The file gets the same name as the class with extension `.cs`

```
BachelorStudent.cs
```

### CC-11 Use Pascal Casing for constants
For example:

```csharp
public const string ProductName = "Visual Studio";
```

and thus not:

```csharp
public const string PRODUCT_NAME = "Visual Studio";
public const string versionNumber = "17.0b2";
```
 
 ### CC-12 Place braces { } after and below the statement, neatly aligned.

```csharp
if (_filled)
{
    rectangle.Fill = brush;
}
else
{
    rectangle.Fill = null;
}
``` 

and **NOT**: 
```csharp
if (_filled) {
    rectangle.Fill = brush;
} else {
    rectangle.Fill = null;
}
``` 

### CC-13 Use a separate line per declaration for variables of the same type

```csharp
 int level; 
 int size;
```  
and **NOT**:

```csharp
int level, size; 
```
